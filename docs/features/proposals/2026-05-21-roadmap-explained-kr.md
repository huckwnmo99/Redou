## 한 문장 요약

> **지난 2주간 "집 구조를 정리(리팩토링)"했으니, 이제 "안전장치(테스트)를 달고, 품질을 측정하고, 고장에 대비"한 다음, 새 기능을 만들자.**

---

## 비유로 이해하기 — Redou를 "자동차 공장"이라 치면

Redou는 논문(원자재)을 넣으면 → 분석·검색·표 생성(가공)을 거쳐 → 지식(완제품)을 내놓는 공장입니다.

| 공장 비유 | Redou 실제 |
|----------|-----------|
| 원자재 투입 | PDF 임포트 |
| 가공 기계들 | MinerU(구조 추출), GROBID(메타데이터), Ollama(AI), 임베딩 |
| 완제품 | 검색 결과, 생성된 표, Q&A 답변 |

### 지금 이 공장의 문제

1. **품질 검사실이 없다 (테스트 부재)** 🔴
   - 제품이 잘 나오는지 **자동으로 확인하는 장치가 없음.**
   - 지금은 사람이 매번 직접 눈으로 확인(수동 walkthrough).
   - → 불량품이 출고된 뒤에야 발견됨.

2. **기계 5대가 모두 돌아가야만 작동, 백업 없음** 🔴
   - MinerU, GROBID, Ollama, 임베딩, DB — **하나만 멈춰도 공장 전체 정지.**
   - 예전엔 "MinerU 고장 시 간이 모드"가 있었는데 **그걸 없앴음.** 이제 MinerU 고장 = PDF 임포트 전면 중단.

3. **제품 품질을 측정할 자(尺)가 없다** 🔴
   - 검색 결과가 "좋아 보인다"고 느낄 뿐, **"몇 % 정확한지" 숫자가 없음.**
   - 측정 못 하면 개선했는지도 모름.

## 그래서 순서대로 이렇게 하자

### 🔧 0단계: 하던 정리 마무리 (1~3일)

- 지금 쪼개는 중인 **PaperDetailView(논문 상세 화면, 1980줄)만 마저 분리.**
- 그리고 **"집 구조 정리는 그만."** 더 쪼개고 싶어도 멈춤.

> **왜?** 구조 정리는 충분히 했음. 계속하면 "정리를 위한 정리"가 됨 (제자리 뛰기).

---

### 🛡️ 1단계: 안전장치(테스트) 달기 ⭐ 가장 중요

**핵심 깨달음:** 지난 2주 정리가 **헛수고가 아님.** 기계들을 따로 떼어놨으니, **이제 각 기계를 따로 검사할 수 있게 됨.**

할 일 (순서):
1. **검사 틀(skeleton) 먼저** — 한 번에 다 만들지 말고, 검사 환경부터 갖춤. (Codex 조언: 가장 어려운 건 화면이 아니라 **"진짜 같은 DB"와 "가짜 AI 응답"을 준비하는 것.**)
2. **전체 흐름 자동 검사 1개** — "논문 1편 넣어서 → 표가 제대로 나오나" 자동 확인. 이거 하나면 공장 전체 점검됨.
3. **고장 상황 검사** — "AI 멈추면?", "빈 결과면?" 같은 경우 + 재사용할 가짜 응답 모음.

> **DB 검사 방식 (Codex 정정):** "가짜 DB(pglite)"가 빠르긴 하지만, Redou는 Postgres 특수 기능(벡터 검색, 권한 규칙)에 의존해서 **가짜 DB는 실제와 달라질 위험**이 있음. → **진짜 Supabase를 격리해서(내 데이터 안 건드리게) 검사하는 게 정확함.** 단순 부품 검사만 나중에 가짜 DB 허용.

> **왜 가장 중요?** 이게 진짜 "디버깅을 쉽게" 만드는 것. 구조를 아무리 잘 쪼개도, 검사 장치가 없으면 불량은 여전히 못 잡음.

---

### 📏 2단계: 품질 측정자(尺) 만들기

**"좋아 보임" → "85% 정확함" 으로.**

할 일:
1. **정답지 만들기** — 논문 10~20편 + "이 질문엔 이 답" 정답 쌍.
2. **3가지 점수 측정:**
   - 관련 내용을 찾았나? (recall)
   - 표의 숫자가 맞나? (accuracy)
   - 없는 걸 지어냈나? (hallucination)
3. **바꿀 때마다 점수 확인** — "설정 바꿨더니 정확도 5% 떨어짐" 을 알 수 있음.

> **왜?** 측정 못 하면 개선했는지 모름. 지금은 AI가 표를 잘 만드는지 "느낌"으로만 판단.

---

### 🔌 3단계: 고장 대비 (백업 장치)

**기계 5대 중 하나 멈춰도 안 무너지게.**

할 일:
1. **시작 전 점검** — 임포트 전에 5대 기계 상태 확인.
2. **고장 시 명확한 안내** — "MinerU 멈춤. 재시도하세요" (지금은 그냥 에러로 깨짐).
3. **간이 모드 부활 — 단, 정직하게** (Codex 정정):
   - "MinerU 없으면 텍스트만이라도" 처리하되, **"이건 텍스트만 추출됨, 표/그림 신뢰도 낮음"이라고 명확히 표시.**
   - 옛 간이 모드(V1)를 MinerU와 동급인 척 **몰래 부활시키지 않음.** 품질이 낮다는 걸 솔직히 알림.

> **왜?** 5대 의존 + 백업 제거 = 깨지기 쉬움. 기능 늘리기 전에 이걸 막아야 함. 단, "낮은 품질을 좋은 품질인 척"하면 안 됨 → 라벨로 정직하게.

---

### 🚀 4단계: 새 기능 만들기 (드디어 사용자 가치)

안전장치 + 측정자 + 고장 대비가 갖춰진 **튼튼한 토대 위에서:**
- 엔티티 그래프 확장 (논문 간 연결, 인용 네트워크)
- supplementary PDF 마무리
- 빈 표 칸 자동 재검색

> **이제 테스트가 있으니, 새 기능 만들어도 기존 게 안 깨짐.**
