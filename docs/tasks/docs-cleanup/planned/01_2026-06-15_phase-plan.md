## 2. 목표 구조 (ledger 철학 적용)

```
docs/
  README.md          ← ★ 단일 진입점 (전체 지도)
  harness/           ← 시스템 현재 진실 (SSOT) · 유지
  tasks/             ← 활성 작업 ledger들 (README + planned/completed/archive)
    docs-cleanup/    ← (이 작업)
    read-only-improvement-advisor/
  backlog/           ← 아이디어 · 유지
  agents/            ← 에이전트 교환 · 유지
  archive/           ← ★ 완료 계획서·제안서·레거시 보관 (이력 보존)
    features/        ← 구현 완료된 fix/new 계획서
    proposals/       ← 옛 제안서
    legacy/          ← 01-Idea, 02-database, 03-frontend, 04-planning
```

원칙: **삭제는 외부/산출물 노이즈에만**(Phase 1). 프로젝트 이력(계획서·제안서·레거시)은 **삭제가 아니라 archive 이동**.
